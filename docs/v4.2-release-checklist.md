# GymOS v4.2.0-rc.1 — Checklist de release

## Código y datos

- [x] Rama de Fase I basada en el cierre de H4.
- [x] Rutinas canónicas de 2–6 sesiones.
- [x] Compatibilidad legacy A/B/C sin D/E/F.
- [x] Migraciones transaccionales e idempotentes.
- [x] Propuestas, activación y rollback aislados por propietario.
- [x] Borrador obsoleto conservado y no mezclado.
- [x] Cambio de propietario limpia estado privado y operaciones pendientes.
- [x] Contraseñas fuera de almacenamiento y logs.

## Seguridad

- [x] Escape común para contenido dinámico.
- [x] Importación bloquea fórmulas, macros detectables, tipos/extensiones incoherentes y CSV injection.
- [x] Descarga histórica restringida a data URLs base64 de tipos admitidos.
- [x] Registro de sincronización sin UUID de usuario, sesión ni objeto Auth.
- [x] Worker no cachea respuestas de Supabase ni otros orígenes.
- [x] No hay credenciales administrativas en el repositorio.

## UX y accesibilidad

- [x] Sin `alert()` genérico.
- [x] Mensajes internos con `role=status`/`alert`.
- [x] Foco visible global.
- [x] `prefers-reduced-motion`.
- [x] Selector de seis sesiones adaptable a móvil.
- [x] Estado vacío de sesión y aviso de draft obsoleto.
- [x] Escape y restauración de foco en el diálogo corporal.
- [ ] Matriz manual 360/390/430/768/escritorio.
- [ ] Prueba manual con lector de pantalla.

## PWA y red

- [x] Caché `gymos-cache-4.2.0-rc.1`.
- [x] Todos los módulos locales en precache.
- [x] Limpieza limitada a cachés GymOS anteriores.
- [x] Fallback de navegación local.
- [ ] Prueba manual de instalación/actualización/offline en dispositivo real.

## Validación

- [x] `node --check` para todos los JavaScript del runtime y worker.
- [x] Suites A–I en verde.
- [x] `git diff --check`.
- [x] Auditorías estáticas de duplicados, scripts, caché, propietario, onclick y claves legacy.
- [ ] E2E de navegador: no disponible en el entorno de auditoría.
- [ ] Smoke test con un proyecto Supabase de staging y RLS real.

## Decisión

El código puede identificarse como `v4.2.0-rc.1` y someterse a validación manual/staging. No debe promoverse a versión estable ni desplegarse a producción hasta completar los elementos pendientes.
